# 外部清单、购物提醒与宿主定时任务

仅在用户要求保存至外部清单、设置购物日程或持续追踪时读取。选择所需部分，不因安装了本 Skill 就启用所有功能。

## 外部清单

先检查用户指定服务是否可用、已连接且有读写权限。不要把工具存在或安装成功当作账户已经连接。用户只要求查询时，不创建文档或数据库。

更新既有 Notion 页面或其他清单前，读取当前内容、用户批注、已买/不考虑状态及最近成功更新日期。沿用已有结构，按候选身份去重；只修改当前购物流程范围内的信息。不覆盖用户的备注和决定。

用户要求新文档但未指定放置位置时，使用服务支持的私人位置；权限不明则先确认位置。不要默认公开分享或擅自移动其他页面。

写入后回读确认关键商品、日期及状态。响应超时或结果不明确时先读回目标，避免重复创建。明确失败可在修正原因后重试一次；仍失败则保留本次已核验资料并报告实际阻碍，不无限重复。

## 购物截止提醒

只有用户已要求为购物截止日设置提醒，且商家官方材料明确给出有效促销/优惠码截止日期时才创建。黑五日期、社区猜测、“售完即止”或库存紧张不构成明确截止日期。

用户没有另定规则时，建议或清楚说明采用截止前 **3 天、1 天，当地 09:00** 的默认值；时区取用户确认的时区，不能从执行机器推断。只创建仍在未来的提醒。不足一天时，如优惠确实值得立即关注，可在已授权范围内安排合理的当天提醒，并说明调整。

创建前读取购物清单的提醒登记和对应日历现有事件。同一商户活动合并多个候选，不为每件商品建重复事件；按活动、截止日期、日历及提前天数去重。

提醒默认设为私人、无参会人、不占用忙闲时间、10 分钟时长、开始时弹窗。关闭自动生成视频会议链接。标题可用“购物雷达｜活动名｜截止前 3 天提醒”。日历能力不支持某字段时明说，不假装已设置。

描述包含：

- 活动与适用条件；
- 商家公布的截止日期、具体时间及商家时区；
- 商家未公布时刻时明确写“具体结束时刻未公布”，不得补成 23:59；
- 官方证据链接、相关商品链接和用户的购物清单链接（如有）。

创建后回读确认事件时间、时区和提醒，再在私人清单登记活动、截止日期及事件标识/链接。延期或用户决定不考虑时，只调整本流程已经获授权的购物提醒，保留其他日程。修改前先读取最新状态；结果不明时先回读，不盲目重复创建。

## 每日或周期追踪

**Skill 是执行说明，不是后台服务。** 只有宿主实际提供定时功能、可在运行时访问所需服务，并且用户要求持续运行，才配置定时任务。缺少调度能力时，交付可复制的任务说明，明确尚未启用定时执行；不要用没有实际执行者的日历事件冒充研究任务。

核对时间、时区及夏令时语义。使用宿主的原生调度工具，更新与本流程匹配的既有任务，避免重复新建。每次运行必须重新核验价格和有效条件，不照抄上次结果。

任务说明至少带入以下**用户确认的配置**，不得直接照搬其他人的值：

```text
按指定时区与频率运行购物雷达。
先读取指定私人清单、最新偏好及最后成功更新日期；
未到计划时间或当日/本周期已成功更新时跳过重复执行。
按用户预算、品类、风格、尺码和收货地区查找真正有价值的大折扣，
优先追踪关注款明显降价；社区只是线索，回商户核验价格及条件。
更新同款、售罄和过期状态，保留用户批注及已买/不考虑决定。
在用户已授权的清单和提醒范围内写入，回读成功后才记本次成功日期。
失败则保留已核验资料并说明完成到哪一步。
```

将具体通知策略写入宿主支持的通知设置，或该宿主要求的任务字段：正常无变化保持安静；显著新优惠、关注款明显降价、重要截止提醒创建成功、运行失败或需用户处理时通知。用户明确要求每日摘要时遵从其频率。不要声称“每日都在后台运行”，除非有已启用任务的证据；首次定时执行未经验证就标为待验证。

交付时分别报告：Skill 已准备 / 清单写入已确认 / 提醒已确认 / 定时任务已配置 / 首次定时执行是否已验证。只列实际涉及的状态。
