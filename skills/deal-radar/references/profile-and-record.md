# 长期偏好与候选记录

建立长期清单、更新既有候选或需要结构化导出时读取本文件。字段按需求使用，不要求用户填完每一项；不要把其他用户的数据当默认值。

## 私人偏好模板

```yaml
shopping_profile:
  delivery_country: null
  timezone: null
  reporting_currency: null
  total_budget: null
  budget_includes: []
  categories: []
  style: []
  preferred_colours: []
  excluded_materials_or_styles: []
  clothing_size: null
  measurements_if_volunteered: null
  shoe_size_and_system: null
  fit_notes: null
  accepts_secondhand: null
  laptop_dimensions_if_relevant: null
  discount_priority: null
  owned_or_already_bought: []
  excluded_items: []
```

只保存用户提供或确认的信息；未知值保持空。身高、体重、尺码与私人文档地址仅在实际有用且用户选择保存时留在私人环境，公开包和样例均不写入。

## 单件候选的最小记录

可写成卡片、列表或用户现有数据库字段，不强制改造既有清单。

- **身份**：品牌、商品名、型号/货号、颜色、适用尺码、商户和商品直链。
- **结论**：值得考虑 / 观望 / 线索待核验；推荐理由和具体待检查项。
- **支付**：当前商品价、运费、已知税费、有效用码条件、到手价；返现等独列。
- **基准**：商户标价/划线价、可验证历史价、各自来源日期、可证实价差；建议目标价与理由单列。
- **适配**：材质、尺码表或实量、具体尺码库存证据、退换窗口与费用；包的开口和可用内尺寸。
- **二手补充**：卖方类型、成色和磨损、配件/来源、验真依据及退货承诺。
- **时间**：核验时间与时区；官方截止日期、具体时刻及其时区（若公布）；结束时刻未知就保留未知。
- **来源**：商品直链、条件/截止日依据、必要的历史价和汇率来源。
- **状态**：候选 / 已买 / 不考虑 / 售罄 / 过期，以及用户批注。

不是每张卡片都要写满。关键缺口直接写“待核验”，不要用长段通用说明掩盖。

## 去重与逐日变化

以“商户 + 货号/型号 + 颜色 + 适用尺码/规格”匹配同一候选；链接追踪参数变化不新建一条。不同商户可并列报价，但共享商品组，避免看起来像多个不同商品。

更新当前价格、库存、条件和状态，保留已买/不考虑及用户批注。历史只记有用变化：核验日期、旧价→新价、库存或条款变化；无变化只更新时间。

比较同款前确认规格一致。二手包不同成色、年份或配件不当作完全可比的“同款降价”。预算说明区分候选合计与已购支出，不能把用户未买的所有候选当成已经消费。
